## 批量巡检报告格式

```markdown
# 技能批量巡检（{N} 个技能）

| 技能 | ERROR | WARN | 主要问题 | 建议 |
|------|-------|------|---------|------|

**优先处理**：{有 ERROR 或高风险的技能及原因}
**建议做全量测试**：{列出}
```

## 写报告的要求

- 每个缺陷都要能回到证据：文件和行号、脚本输出原文、用例结果。
- 修复动作写到可以直接执行的程度（改哪里、改成什么），不写“建议优化”。
- 不建议拍脑袋的行数目标；建议精简时说明是去重、消冲突还是下沉，以及内容移到哪里。
- 不给创作类技能加数量配额，不建议一刀切的禁用词表。
- 结论、缺陷清单、分层结果三处互相一致；报告末尾不写自我评价。
